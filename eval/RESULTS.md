## 2026-09-20 실데이터 후 재설계 — 사칭 · 살포 · 게이트

첫 실제 Threads 수집분을 보고 표적을 다시 정했다. 잡아야 하는 것은 **해외 등록 계정이 한국 페르소나로 증권사·대기업
직원을 사칭**하고(사원증·급여명세 사진), **같은 문구를 여러 일회용 계정에 살포**하는 형이다. 텔레그램 유도는 있으면 좋고 없어도 된다.
기존 엔진은 "연락채널 없으면 HIGH 불가" 게이트 때문에 이 형을 구조적으로 놓쳤다.

### 1. 사칭 범주 (`lexicon.ts: impersonate`)
- `sub: "institution"` — 대신·삼성·키움·미래에셋·한투·NH·KB·신한·하나·메리츠·유안타, 삼성전자·SK하이닉스·현대차·LG·한국은행, 증권사·자산운용. **w 0.3 (3점)** — 이름 단독은 거의 점수가 없다.
- `sub: "credential"` — 재직중·재직·현직·근무중·임직원·직원입니다(7~9점), 사원증·급여명세·재직증명·내부정보(10점), 명세서·내부자·인사이더, 회사에서·팀장·부장·과장·매니저(3~4점). 범주 상한 20.
- `OFFER_PATTERN` — "드릴게요/공유해/상담해드/문의는/댓글 남겨/디엠" 처럼 **주는 쪽** 표현만. "알려주세요" 같은 구하는 쪽은 제외 — 취준 글과 갈리는 지점.

### 2. 결합 규칙 (`score.ts`)
- `impersonate:institution+credential` **+25** — 기관명 + 재직·증빙 + (투자·수익·연락 어휘 **또는** 제안 표현). 셋 중 하나라도 빠지면 0.
  "삼성전자 재직 중인데 구내식당…"(12점) 과 "대신증권 재직중, 사원증 인증, 종목 정보 드릴게요"(83점) 가 여기서 갈린다.
- `impersonate:institution+credential+invest` **+10** — 위 결합에 투자·수익·연락 범주가 실제로 있을 때.
- CTA 가점은 연락채널 **또는 사칭 결합**이 있을 때 계산한다.

### 3. 살포 신호 (`AccountFeatures.clusterAccounts`)
- 이 글과 근사 중복(Jaccard ≥ 0.75)인 글을 쓴 **서로 다른 계정 수**(본 계정 포함). 2 → +15, 3 → +25, 5+ → +32.
- `clusterSize`(같은 계정의 반복)는 그대로 두고 상한만 15 → 20.
- `collector/score-local.ts` 가 계정 경계를 넘어 전체 항목을 LSH + union-find 로 묶고 `clusterAccounts` 를 넘긴다. 출력에 "같은 문구를 쓰는 계정 묶음" 절 추가.
- `src/lib/pipeline.ts` 는 클러스터 구성원(또는 이번에 찾은 근사 중복 후보)의 distinct account 수를 넘긴다.

### 4. HARD GATE 변경
HIGH 허용 조건: **연락채널 > 0 ∨ 사칭 결합 발화 ∨ clusterAccounts ≥ 3**. 아니면 69 상한(`gate:no-contact` 유지, 문구는 세 조건을 모두 언급).
veto·counter 는 그대로.

### 5. 코퍼스 추가 (25건)
- scam 10 + 변형본 5: 사칭형. 절반은 텔레그램 없음(댓글·DM 유도). 전부 HIGH (94~100).
- benign 10: 직원 잡담(삼성전자 구내식당·하이닉스 급여명세서·미래에셋 임직원 할인), 취준(하나증권 면접), 뉴스(대신증권 실적), 사원증 분실, 이직 고민, 신입 일상. 9건 LOW(6~20점), 1건 REVIEW(b128 뉴스 — % + 프로필 링크 결합, 42점).

### 6. 표시 문구 (`src/lib/labels.ts`)
기계 라벨은 지표만: HIGH "강한 신호" / REVIEW "신호 감지" / LOW "신호 미약" / UNKNOWN "수집 기록 없음". 사람 검토 결과만 판단 어휘: CONFIRMED "검토 완료 · 사기 확인" / CLEARED "검토 완료 · 해당 없음".
근거마다 `src/engine/explain.ts` 가 무엇이/왜/실제 예시/정상 사용 4단락을 붙인다(리포트 JSON `rationale[]` 에도 포함).

### 남은 약점 (재설계분)
- **s014/s015/s088 류** — "○○증권 리서치센터 10년 근무", "현직" 만 있고 사원증·명세 없이 텔레그램만 있는 형은 REVIEW(43~48). 실제 기관명이 없어 사칭 결합이 안 붙는다. 기관명 없는 "증권사 출신" 은 일반 광고와 구분이 어려워 의도적으로 두었다.
- **뉴스 + 프로필 링크(b128)** 가 42점 REVIEW. 기사 veto 는 "기사" 단어가 아니라 형식(출처:)에만 걸리기 때문. 뉴스 요약 계정이 프로필 링크를 달면 이 구간에 남는다.
- **살포는 코퍼스에서 측정되지 않는다.** 게시물 1건 단위라 `clusterAccounts` 가 비어 있다. 단위 테스트(계정 3개 → HIGH, 무해 문구 8개 계정 → not HIGH)로만 검증.
- **파이프라인의 살포 가점은 나중에 들어온 계정에만 붙는다.** 먼저 수집된 계정은 클러스터가 커져도 재계산되지 않는다(연락처 공유는 재계산함). 다음 단계.

## 무엇을 바꿨나

### 1. HARD GATE — 연락채널 없으면 HIGH 불가 (`score.ts`)
`categories.contact <= 0` 이면 점수를 `NO_CONTACT_CAP = 69` 로 눌러 HIGH 를 막고,
`gate:no-contact` 근거를 남긴다. 리딩방 유인은 정의상 "어디로 오라" 가 반드시 있다.
그게 없는 글(투자 자랑·시황 과장·수익 인증만 있는 글)을 HIGH 로 올리면 신고서에서 방어할 수 없다.
프로필 외부 링크가 메신저·링크모음(`t.me`, `open.kakao`, `linktr.ee` …)이면 이것도 연락채널 신호로 친다.

### 2. 맥락 상한(veto) — 점수를 깎는 대신 자동 판정을 포기 (`lexicon.ts: VETO_PATTERNS`)
감점은 강한 유인 어휘가 쌓이면 뚫린다. 그래서 다음 신호는 **상한**으로 건다.

| 신호 | 상한 | 근거 |
|---|---|---|
| 등록·신고·인가 번호 명시 (`제2019-0000호`) | 39 | 합법 등록 유사투자자문업체의 광고 형식 |
| 법정 고지문 (원금손실 가능 / 투자판단 본인 책임 / 권유가 아님) | 45 | 유인글은 이 문구를 쓰지 않는다 |
| 기사·보도자료·공시·출처 인용 | 45 | 뉴스 공유 계정 |
| 공공기관 창구 (1332 / ECRM / 사이버수사대 / 소비자경보) | 39 | 금감원·경찰 캠페인 |
| 유인 성격 부인·해명 ("리딩방 아니에요") | 69 | 해명글 |
| 유인 문구 **인용** + 풍자/해설 맥락 | 59 | 밈·풍자·연구 |
| 피해·경고 강한 어휘 1개 / 2개 이상 | 69 / 55 | 피해 후기·경고글 |
| 팔로워 20,000 이상 | 69 | 언론·인플루언서는 사람이 본다 |

주의해서 고른 지점: **"금융감독원"·"뉴스" 단어 자체는 veto 가 아니다.** 사칭형("금감원 등록 자문사와 제휴", "MBC 뉴스에 나온 기법")이 그 단어를 그대로 쓰기 때문이다.
veto 는 *번호 형식*, *고지문 형식*, *출처 표기*처럼 위조 유인이 낮은 **형식**에만 건다.

## 남은 약점

1. **초단문 유인은 못 잡는다.** "오늘 종목 나갔습니다. 못 받으신 분 디엠"(57점) 처럼
   어휘가 3개도 안 되는 댓글은 본문만으로 70을 넘길 수 없다. 이건 의도된 한계다 —
   반복성(`clusterSize`)·살포(`distinctTargets`) 신호가 붙는 실제 파이프라인에서는 넘어간다.
   코퍼스는 게시물 1건 단위 판정이라 이 신호가 비어 있다.
2. **"톡방/단톡"만 쓰고 플랫폼명을 숨기는 형**(s075: "단톡 자리 정리했습니다. 문의는 프사 링크", 66점)은
   REVIEW 에 남는다. 가중치를 더 올리면 팬덤·스터디 단톡 모집 글과 충돌한다.
3. **경고 어휘 1개 veto 의 대가.** "신고했습니다" 같은 단어가 유인글에 섞이면(자작 후기형)
   자동으로 REVIEW 로 내려간다. 정밀도를 위해 의도적으로 지불한 재현율이다.
4. **benign 상단 여유가 69/70 로 빠듯하다.** 피해 경험담(b006)·해명글(b106)이 상한 덕에 69 에 걸려 있다.
   상한이 없으면 바로 오탐이 된다 — 즉 precision 1.000 은 veto 규칙에 상당히 의존하고 있으며,
   새 어휘를 추가할 때마다 이 두 건을 회귀 케이스로 확인해야 한다.
5. **코퍼스는 합성이다.** 문구는 실제 유인 패턴을 모사했지만 분포는 실제 수집물이 아니다.
   `/api/feedback` 으로 들어오는 실제 이의 제기를 코퍼스에 추가해 나가는 게 다음 단계다.
6. **계정 신호 의존.** HIGH 117건 중 상당수가 버너 프로필(신규·저팔로워·외부 링크) 가점을 받는다.
   계정 메타데이터가 없는 텍스트-온리 판정(`/analyze`)에서는 재현율이 이보다 낮다.
